# Start

## Entry Identity

- Name: Start
- Version: 1
- Canonical Identifier: tiinex.core.entry.start.v1
- Entry Family: tiinex.guided-entry.native.v1
- Human Label: Start

## Purpose And Scope

- Purpose: Establish an initial qualified working orientation from the available carried material before substantive work begins.
- In Scope: initial context recovery, relevant current boundaries, material uncertainty, participant-facing orientation
- Out Of Scope: automatic task selection, work transfer, recipient authority, acceptance, or substantive execution

## Entry Context

- Entry Target: the qualified carried Workspace context available to the receiving session
- Required Context: the carrier Start/bootstrap path, qualified Workspace/material projection, and any explicitly selected Session Role or participants
- Relevant Context: current lineage leaves, recent material, declared ownership boundaries, and implementation state where they materially affect initial orientation
- Context Exclusions: carriage alone does not make material controlling, authoritative, current, or applicable

## Preparation

- Preparation Method: qualify the carried context and recover the smallest current material picture sufficient to understand where the session is starting
- Reconciliation Policy: where materially relevant representations disagree, preserve the disagreement and resolve currentness or scope before silently choosing one as controlling
- Discovery Breadth: broaden beyond the first artifact or Workspace when the selected Session Role or discovered ownership boundaries require it for a truthful initial picture
- Currentness Policy: prefer qualified current lineage, explicit supersession, and current implementation evidence over filename order or first encounter
- Uncertainty Policy: state unresolved currentness or authority when it affects the next decision rather than filling it with assumptions

## Entry Method

- Method: establish the initial working context, identify what appears current and what remains uncertain, then present the most relevant immediate context before substantive work
- Readiness Boundary: the receiving session can operate within its selected Role boundary without relying on an obvious unresolved contradiction about current context or authority

## Presentation And Interaction

- Intended Audience: the Roles or people participating in the receiving interaction
- Presentation Guidance: present the useful current picture in a concise, scan-friendly, human-facing form; lead with what is current or decision-relevant rather than narrating successful bootstrap or qualification mechanics
- Preference Sources: apply qualified presentation or communication preferences from participating Role material when available
- Diagnostic Detail Policy: foreground bootstrap, qualification, or diagnostic detail only when it materially changes the conclusion, blocks progress, or is explicitly requested

## Interpretation Limits

- Does Not Establish: Handoff routing, recipient authority, Role-holder state, participant authority, acceptance, task ownership, work transfer, or completion
- Must Not Be Inferred: that carried material is current or controlling merely because it is present, encountered first, or appears active by label

## Portability Notes

- Portable Semantics: establish a truthful initial orientation before substantive activity begins
- Environment Assumptions: access to the qualified context required to establish the initial orientation
- Non-Portable Details: Tiinex carrier commands, host UI, model provider, filesystem paths, and transport controls
