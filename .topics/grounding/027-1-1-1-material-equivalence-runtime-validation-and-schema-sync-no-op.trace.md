# Material Equivalence Runtime Validation And Schema Sync No-Op

## Objective

Close the remaining Core split-brain around immutable schema material identity so reference qualification, exact runtime validation, Repair eligibility, and deterministic Docs-to-Core synchronization agree that a newer repository commit does not invalidate or rewrite byte-identical canonical schema material.

## Done Criteria

- An older immutable Current Schema locator at the same canonical repository/path qualifies for exact runtime validation when explicit resolution proves the same schema material bytes.
- The same case emits no schema-authority warning, no stale-permalink diagnostic, and no Repair action solely because a newer commit exists.
- Different material, a different canonical repository/path, or missing material-resolution evidence remains fail-closed.
- Runtime validation and reference qualification consume the same Core-owned material-equivalence and target-resolution primitives rather than parallel commit-freshness rules.
- Published Docs-to-Core schema sync preserves prior immutable per-schema publication bindings when schema bytes are unchanged.
- A published sync over a newer Docs commit with an identical schema snapshot is a generated byte no-op and does not rewrite unchanged generated files.
- A real schema byte change rebinds affected schema material while unchanged schema bindings remain stable.
- The Windows recipient-return UX regression checks structured invocation semantics instead of OS-specific shell quoting.
- Focused Core material-identity/reference/sync/authoring tests, Package V1 transport sanity, portable smoke, and npm pack dry-run pass.

## Scope

Core schema material identity, schema-reference resolution, exact runtime validation authority, shared audit plumbing, deterministic native schema synchronization, and the OS-agnostic recipient-return test assertion.

## Dependencies

- Parent Task `027-1-1` native Schema Pack and deterministic Docs-to-Core synchronization.
- Existing Core `schemaMaterialIdentitiesEquivalent` and `schemaReferenceAuthorityWithEquivalentResolvedTarget` primitives.
- Exact host-supplied schema reference resolution evidence; hosts remain sensors/presentation and do not redefine semantic validity.
- Canonical Docs schemas remain unchanged in this tranche.

## Exclusions

- No canonical Docs schema revision.
- No mass permalink refresh of historical artifacts.
- No VS Code-specific semantic validator.
- No automatic Repair when exact replacement cannot be proven.
- No repository-tip freshness rule as semantic authority.
