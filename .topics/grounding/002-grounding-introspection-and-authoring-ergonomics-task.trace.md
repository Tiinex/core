# Grounding Introspection And Authoring Ergonomics

## Objective

Make current qualified grounding facts cheaper and safer for a fresh Role to understand without reading Core implementation, while preserving the first-run semantic boundaries and fail-closed behavior.

## Done Criteria

- Grounding/introspection exposes bounded route authority, source-state provenance and unresolved wider orchestration state without promoting carried Roles/endpoints/process inventory into semantic authority.
- Existing first-return source-state distinctions and exact-source blockers remain regression-covered.
- Authoring/qualification errors relevant to first-run work provide actionable contract guidance where deterministic and safe, including valid-domain/Parent/preflight guidance when available.
- Recovery/package preflight surfaces missing required carried Workspace selection before manufacture where the requirement is mechanically known.
- Process applicability is projected only from authority already explicit in qualified semantics; otherwise Tooling returns a precise unresolved semantic blocker.
- Focused and broad Core qualification remain green and the result is returned through a qualified Loom-to-Anchor Handoff.

## Required Work

- Add or harden a compact explain/introspection surface for current holder binding, selected-route authority, writable/read-only boundaries, source states, explicit participant facts, bounded `grounded-to-act`, wider orchestration diagnostic and unresolved authority. Prefer provenance for each projected fact over new semantic states.
- Preserve the first-return invariant that carried Role pointers are grounding/discovery only and do not create semantic participation.
- Preserve complete/bounded/cache/qualified-reference/unavailable source distinctions and make exact blockers identify required material, owner/basis and blocking reason without auto-discovery.
- Improve authoring diagnostics where the first run proved needless friction: invalid enum/domain values should expose allowed contract values or exact contract path when safe; semantic Parent requirements should identify the missing explicit Parent action; manufacture/preflight should identify Required Context Workspace selections before a doomed output attempt where deterministically knowable.
- Expose why an explicit projection is empty/unresolved where current authority supports the explanation, especially participant context and orchestration readiness. Do not fill the projection heuristically.
- Treat process applicability as an unresolved semantic dependency unless the current integrated source already contains an explicit qualified declaration pattern. Implement only generic projection hooks that consume explicit authority; do not scan Business process inventory or infer applicability from Role/process carriage.
- Add focused adversarial tests and run the complete Core validation suite.

## Inputs

- Integrated Core first-return implementation and Evidence.
- Integrated Docs first Axiom disposition as current semantic boundary.
- Current Business Epic, Anchor Role continuation, process lineages and second-tranche integration Task as read-only organizational evidence.

## Scope

Shared host-neutral Core tooling: grounding/readiness/source/participant explanation, provenance, authoring error ergonomics and manufacture/preflight diagnostics.

## Dependencies

- Qualified Loom first-return thin-lineage grounding projection implementation and Evidence.
- Current Business Thin-Lineage Anchor Grounding And Orchestration Reliability Epic and second-tranche integration Task.
- Current Docs Axiom thin-lineage semantic disposition as semantic authority/context.
- Loom first-run retrospective as diagnostic evidence for friction and explainability gaps.
- Process-applicability semantics remain Axiom-owned; Core may implement only already-authorized facts and must fail visibly otherwise.

## Exclusions

- No Business or Docs mutation.
- No process semantic invention.
- No repository-global process/Role discovery as authority.
- No Extension VS Code mutation unless a new shared-Core blocker proves host-specific work is necessary; return that blocker instead.
- No remote source acquisition.

## Return Boundary
