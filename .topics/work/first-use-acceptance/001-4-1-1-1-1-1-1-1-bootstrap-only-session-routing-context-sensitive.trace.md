# Bootstrap-Only Entry Choice — Context Before Default

## Supported Claim Or Question

- Supported Claim Or Question: When a valid bootstrap-only carrier has neither Workspace material nor a selected session Entry, can its canonical Start guide a receiver to distinguish a fresh goal from ongoing host-conversation work without automatically activating Getting Started or manufacturing work authority?
- Evidence Role: Source-grounded local candidate and bounded regression; not proof of improved independent ChatGPT behavior.

## Provenance

- Known Source: qualified 013 17-Workspace carrier and its own runtime/Start; direct inspection of Core Package V1 Start renderer, Guided Entry catalog projection, Native Getting Started v2 Entry and Docs first-use/continuity guide; Sigma's observed 012 creation/recovery and subsequent correction that no Entry should be a universal default.
- Preservation Basis: only Core's canonical Package V1 Start renderer, its directly related regression test, and this Evidence change in the candidate; other Workspaces and carrier 013 remain unchanged.
- Provenance Limits: a receiver's active conversation is host context, never derivable from the package. A qualified new record may describe evidenced prior conversational work but does not retrospectively certify the conversation as Tiinex lineage.

## Evidence Material

- missing-no-entry-route
  - Material: Core Guided Entry projection and ordinary 013 bootstrap-only Start.
  - Material Kind: source inspection
  - Description: no purpose Entry is automatically selected when the operator omits one. The catalog exposes possible qualified Entries, while Start correctly forbids inferring carried Workspace or transferred work authority. No current bounded instruction helps choose between a fresh host conversation and a conversation already holding substantive work.
- conditional-start-candidate
  - Material: Core Package V1 Start rendering function.
  - Material Kind: bounded code change
  - Description: a conditional paragraph only on bootstrap-only Start instructs the recipient, when no session Entry is selected, to use qualified Tooling discovery and distinguish fresh user goals from ongoing work. Fresh goals may use qualified Getting Started; ongoing work first requires evidence-based reconstruction of outputs, decisions, uncertainties, source provenance and next steps before offering qualified Workspace persistence. Explicit Entry choices, Workspace carriers and routed Handoffs are not changed.
- focused-regression
  - Material: Core Package V1 direct bootstrap and Workspace carrier tests.
  - Material Kind: local executable test
  - Description: two directly affected tests pass; generated bootstrap Start contains conditional guidance, ordinary transport does not duplicate it, and pointerless Workspace transport remains unchanged. Full fresh-host independent behavior is not tested by these assertions.

## Preservation And Fidelity

- Preservation State: candidate Core-only adjustment; no new Entry, schema family, sidecar, Target, Process or auto-selecting mechanism.
- Fidelity Notes: Start remains authoritative for package bootstrap; guided selection remains a separate operator/session intent. A bootstrap-only carrier does not itself describe whether the host conversation is new or already active. Qualified authoring and consent remain prerequisites for durable new Workspace material.
- Known Losses: none to existing route/Workspace semantics intended. The added Start note costs a short paragraph and has not undergone independent behavioral comparison.

## Interpretation Limits

- Does Not Prove: that absent an explicit Entry the LLM will autonomously call the right Tooling command, that contextual reconstruction is complete, that new Workspace continuity is accepted by the user, or that previous chat history became qualified by association.
- Must Not Be Treated As: permission to auto-create a Workspace, infer Handoff/Role authority, treat chronological chat content as exact historical lineage, or override explicitly chosen Entry/Target.
- Not Yet Used As: independent first-use acceptance or a reason to replace an operator-selected Entry.
- Next Qualification: manufacture bootstrap-only and full-carrier candidates using the changed runtime, test their Start and transport independently, then use an uncoached new-vs-ongoing host test only if the local carriers pass.
