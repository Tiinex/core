# First-Use Acceptance: Blank Workspace to Useful LLM Continuity

## Objective

Establish a qualified, minimal first-use path for a novice who initializes Tiinex in an empty local directory and begins an ordinary LLM chat, without a prepared Handoff, curated Role, or expert instructions.

## Done Criteria

- Initialize works without Git and produces a qualified local Workspace descriptor.
- A user can discover Tiinex in a normal first chat and create the smallest meaningful, qualified artifact structure.
- Native Start, Explore and Resume Entries are discoverable through qualified carrier transport where applicable.
- A second fresh session can reconstruct and explain the current work without fabricated authority or unnecessary artifacts.
- The installed VSIX and real chat path are checked in a blind Batch 1, followed by a distinct release-candidate Batch 2 if needed.

## Scope

- Fix the confirmed portable CLI native-Entry content-source forwarding omission in Core; add focused regression coverage.
- Preserve the distinction between Core root-artifact creation and the VS Code host's qualified-Workspace selection policy.
- Do not claim that carrier-based Guided Entry is equivalent to automatic discovery in an ordinary chat.
- Prioritize at most two human-operated first-use batches before release consideration; minimize bloat and unrelated schema changes.

## Dependencies

- Exact installed Core/VSIX compatibility, Node prerequisites, and novice-visible Copilot surface must be tested separately from source/runtime checks.
- Work is local and unpublished; no remote writes, repository publication, or Marketplace release is authorized by this Task.
