# Getting Started Documentation Boundary — Qualified Local Carrier Evidence

## Supported Claim Or Question

- Supported Claim Or Question: whether the provisional 041-1 continuation carrier exposes the actual Docs Getting Started material through a qualified carried Workspace, while a zero-Workspace bootstrap-only carrier truthfully preserves its absence and still makes the reusable Getting Started Entry available.
- Evidence Role: a bounded local, read-only source/CLI verification of Docs availability, provenance and loss boundaries; NOT independent model behavior or installed host acceptance.

## Provenance

- Known Source: accepted 041 checkpoint; 041-1 pending Sigma acceptance (not treated as accepted); qualified zero-Workspace `tiinex-bootstrap-replacement-002` from Sigma; qualified Native Getting Started Entry; the locally manufactured 041-1 runtime.
- Preservation Basis: exact carrier byte inspection, package-qualified Workspace archive, Docs self/Parent integrity, bootstrap manifest content-source discovery, CLI orientation/catalog and explicit negative mutation of an in-memory archive copy.
- Provenance Limits: local Linux Node 22.16.0 tooling and in-memory archive verification. No GitHub read is promoted to package authority; no live Windows VSIX/Copilot cold start or independent LLM trial took place.

## Preservation And Fidelity

- Preservation State: this Evidence is authored in the Core first-use acceptance lineage; the package remains a complete pointerless Workspace carrier, not loose files or a `.patch`.
- Fidelity Notes: 041 is the accepted basis; 041-1 and any later continuation require Sigma's explicit gate. No `.guidance`, JSON sidecar, new schema, automatic Workspace ownership or remote mutation was introduced.
- Known Losses: disposable console and scratch test receipts outside the carrier are summarized here rather than falsely described as carried primary evidence.

## Interpretation Limits

- Does Not Prove: automatic Docs retrieval with bootstrap-only, independent human/LLM uptake of the Entry, Windows installed VSIX experience, successful novice first-use work, correct exit/termination or end-to-end recovery across fresh chats.
- Must Not Be Treated As: an instruction to add mandatory Docs reading on every cold start; absent Docs guidance is a declared capability boundary, not a reason to invent a manual.
- Not Yet Used As: final Sigma acceptance, release or publication approval, validation of bootstrap-only automatic Docs retrieval, or independent model grounding proof.
- Remaining Acceptance: independent Guided Entry and ordinary VS Code first-chat batches, genuine work/save/exit/resume outcomes, and host-specific test receipts. If those fail, prefer a reproducer before changing contracts or implementation.
