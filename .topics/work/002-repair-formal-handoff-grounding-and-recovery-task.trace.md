# Repair Formal Handoff Grounding And Recovery

## Objective

Repair the Core grounding seams exposed by the formal `tiinex-018` cold start so qualified carried material is consumed before external recovery, exact host recovery retains source identity, and optional Handoff return-resolution aids do not incorrectly block unrelated act readiness.

## Done Criteria

- A commit-pinned GitHub Parent already present in a qualified carried Workspace resolves without network recovery when repository/path identity matches and declared Parent integrity proves the carried bytes are exactly the intended target.
- Moving/live same-path material with different bytes does not satisfy a pinned Parent merely because repository/path match.
- Qualified Workspace snapshot material projects enough durable source identity for exact repository-aware lineage matching without turning package placement into semantic authority.
- Accepted GitHub repository-read recovery retains provider/source identity needed by exact lineage matching; the common `ground --host-result` seam closes the same blocker it recovered.
- `Return To Reference` remains an optional Handoff resolution aid as defined by the schema. A readable `Return To` without a reference does not block starting unrelated bounded work; absence remains visible for return authoring/resolution when relevant.
- Diagnostics preserve distinctions between missing material, source-identity mismatch, integrity mismatch, and authorization/readiness boundaries where practical.
- A qualified child with an exact commit-pinned Parent recovery locator, declared Parent integrity, and valid self integrity may form a compact cold-start recovery boundary without eagerly loading historical ancestry; mutable or integrity-free missing ancestry still fails closed.
- A stable carrier major manufactured from a qualified parent carrier preserves all unchanged complete parent Workspaces by default while explicit current Workspace roots replace matching ids; bounded non-major delegation/return carriage remains explicitly scoped.
- Exact process/guidance applicability can be established by one qualified Relation that explicitly binds the Handoff-selected guidance set to current work; Required Context membership alone remains insufficient and Core does not normalize Relation Type prose into global semantics.
- Exact direct Parent ancestry between qualified Project/Task artifacts projects work provenance without requiring a duplicate `work-provenance` Relation; unrelated Parent shapes remain outside that projection.
- Regression coverage includes the real failure shapes above plus existing lineage/Handoff recovery behavior.
- No OpenAI/ChatGPT policy is added to Core and no remote mutation is performed.

## Scope

Core host-neutral lineage source matching, carried Workspace materialization, host receipt normalization/recovery, grounding readiness/continuity, explicit Relation-bound guidance applicability projection, Project/Task Parent work-provenance projection, stable carrier manufacture defaults, and focused regression tests only.

## Dependencies

- Controlling Business Project: Grounding And Continuity Readiness at immutable Business commit `9fc62b5fa91aab00731d4a4f67ac53f495ece38d`.
- Handoff schema contract: `Return To Reference` is optional and must not silently become a stronger Core requirement.
- Portable session continuity process remains content/policy outside Core; Core implements mechanics rather than provider or organization policy.

## Execution Order

1. Reproduce and protect the exact carried-Parent failure with a focused lineage test.
2. Preserve repository/provider identity on qualified carried Workspace and accepted host-recovery material.
3. Permit pinned-ref relaxation only when repository/path remain bounded and Parent integrity verifies exact bytes.
4. Remove the incorrect act-readiness dependency on optional `Return To Reference` while keeping return-resolution visibility.
5. Qualify compact immutable Parent recovery as a cold-start boundary without promoting mutable/unverified ancestry.
6. Make parent-carrier Workspace reuse the default for stable carrier majors while preserving explicit bounded-carrier behavior.
7. Project exact selected process applicability from a qualified Relation binding without inferring from carriage or Required Context membership alone.
8. Reuse exact resolved Project/Task Parent ancestry as work provenance instead of requiring duplicate relation authority.
9. Run only focused regression coverage for changed seams, then replay the real carrier cold-start path before any stable checkpoint is proposed.
