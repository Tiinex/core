# Shared Tiinex authoring ownership and bootstrap independence

## Discovery Intent

Establish where shared Handoff transitions and their generation artifacts must live so Core-only and VS Code consumers have identical foundational authoring capabilities without introducing an App dependency.

## Discovery Field

- Field: Core, App and VS Code qualified authoring-material ownership and native bootstrap projection.
- In Scope: Core shared Handoff authoring, App duplicates, VS Code adapter and bootstrap integration.
- Out Of Scope: Site and Chrome feature changes; unqualified migration of existing Site-local transitions.

Read-only examination of the qualified Core, App and VS Code snapshots in the latest pointerless evaluation carrier; native schema pack, portable Transition catalog, bootstrap enumeration, App schema assets and VS Code adapter. Site and Chrome Extension remain outside the work scope.

## Discovery Method

- Method: exact source inspection, native bootstrap projection, cold CLI replay and local regressions.

Compared App Handoff schema and transition assets against Core native Handoff schema, inspected the active Transition catalog and bootstrap material graph, and executed Core-only versus App-supplied Handoff projection. Identified Site-local authored artifacts and App acceptance fixture dependencies before removing material.

## Discovery Boundaries

A duplicate filename is not proof of semantic equivalence. The Core native schema pack has one qualified canonical Handoff schema; external Workspace transitions remain independent sources, and discovery is not execution authority. Existing App-specific Site transitions cannot be reclassified as Core semantics solely to empty a folder.

## Discovery Outcome

- Core supplies Handoff schema and executable creation contract but originally projected zero qualified Handoff authoring profiles without App material.
- App supplied three shared Handoff Transition Definitions, three Generation Authorities, their Companion and Semantic Package; they are candidates for migration to Core native runtime assets.
- Existing App also contains older Site-specific transitions and legacy local readable schema snapshots referenced by historical acceptance tests; wholesale deletion would risk unrelated breakage.
- A Core-native material provider can project shared Handoff schema text from the existing native pack plus authored companion/transition material. The portable bootstrap must preserve exact authored bytes and verify generated projection freshness.

## Interpretation Limits

This discovery does not authorize moving Site-specific App transitions to Core, changing Site/Chrome architecture, auto-executing discovered transitions or inferring npm package autoloading. Broader App schema cleanup remains a separately qualified migration.
