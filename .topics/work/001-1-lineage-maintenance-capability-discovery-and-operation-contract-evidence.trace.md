# Lineage Maintenance Capability Discovery And Operation Contract Evidence

## Supported Claim Or Question

- Supported Claim Or Question: whether current Tiinex Core/VS Code tooling already supports safe lineage Move, re-dimensioning, and Prepend semantics, and what minimal shared operation contract is justified before implementation work begins.
- Evidence Role: bounded discovery and contract evidence for the Core lineage-maintenance Task; it establishes current capabilities, missing surfaces, and semantic invariants without claiming implementation.
- Target Artifact: Deterministic Lineage Maintenance Projection And Apply.
- Review Context: process-directory relocation exposed directory-local filename dimensions such as `001-2` and `004` surviving inside newly isolated process directories even though current inspection remained clean.

## Provenance

- Known Source: exact carried Major 017 Core, Business, Native, Docs, and VS Code Workspace material in Handoff Package `017-1-1-1-1-1`.
- Preservation Basis: read-only source/test/operation inspection of Core directory-local allocation, lineage resolution/segment projection, Scaffold relocation, lineage-integrity apply, and VS Code command contributions; no source mutation occurred during discovery.
- Provenance Limits: this Evidence does not establish final API names or prove that every arbitrary disconnected artifact set can be re-dimensioned deterministically; ambiguous selections must remain blocked.

## Evidence Material

- Material: current directory-local allocation and lineage-maintenance capability inventory plus the bounded Move/Prepend operation contract derived from observed maintenance cases.
- Material Kind: tooling capability discovery and semantic operation-contract evidence.
- Directory-local Allocation: Core `allocateRootArtifactPath`, `allocateDirectoryArtifactPath`, and directory-local continuation allocation choose numeric coordinates from the target directory rather than carrying the Parent directory's filename dimension into a new directory.
- Semantic Parent Authority: Core `resolveLineage` creates Parent edges from declared Parent Trace/Origin/recovery authority and integrity qualification; it does not derive semantic Parent from the numeric filename shape.
- Segment Discovery: the lineage projection surface already contains semantic `segment` selection between loaded Parent-connected endpoints, but it is read-only and does not provide path mutation/re-dimension apply.
- Existing Relocation Primitive: `projectScaffoldArtifactRelocation` can map path-prefix subtrees, rewrite relative/Workspace-qualified current references, update locally resolvable Parent integrity Parent-first, and reseal changed outputs. It preserves filenames below the mapped prefix and is therefore insufficient for isolated directory-local re-dimensioning or explicit segment/set Move.
- Existing Integrity Primitive: lineage-integrity apply already demonstrates exact-plan validation, per-artifact approval, Parent graph construction, topological cascade, representation guards, receipts, and post-repair audit; it does not mutate artifact paths or provide Move/Prepend semantics.
- Portable Operation Gap: current portable operation inventory contains lineage resolve/search/print/integrity surfaces but no Move Lineage, Re-dimension Lineage, Normalize Directory Namespace, Prepend, or Insert Ancestor operation.
- VS Code Gap: current command contributions expose lineage viewing/toggling and transport controls but no lineage Move/Prepend/rename maintenance command.
- Validation Gap: generic artifact/Workspace inspection has no general directory-local numeric namespace qualification; the invalid post-relocation process dimensions therefore remain structurally visible to humans while inspect can remain clean.

## Operation Contract

- Invariant: filename dimension is a directory-local navigation/placement coordinate and is not semantic identity or semantic Parent ancestry.
- Move: changes location/path coordinates and local filename dimensions while preserving the qualified semantic Parent graph by default.
- Move Selection: authority is an exact qualified artifact set/graph selection. Filename prefix may assist UX or sanity checks but must never be selection authority.
- Whole Move Example: moving a complete local lineage into an empty directory may rebase `001`, `001-1`, `001-1-1` to the same compact local shape in the target while preserving all semantic Parent edges.
- Segment Move Example: from local coordinates `001`, `001-1`, `001-1-1`, `001-1-1-1`, moving the middle artifacts currently named `001-1` and `001-1-1` may leave `001` and the former `001-1-1-1` in the source; the survivor may compact to local `001-1` while its semantic Parent remains the moved artifact in the target directory. Local numeric adjacency must not manufacture a Parent edge to source `001`.
- Prepend / Insert Ancestor: intentionally changes the semantic Parent graph. Inserting ordered artifacts `[X, Y]` before target `B` on edge `A -> B` yields `A -> X -> Y -> B`; insertion before a semantic root makes `X` the root, then `Y`, then the prior root. The affected local filename lineage shifts deeper, while unrelated major/sibling roots remain untouched.
- Reorder Boundary: arbitrary sibling/major insertion/reorder is a different, wider-cascade operation and is explicitly deferred until a real use-case justifies it.
- Namespace Maintenance: ordinary Reduction/deletion does not auto-renumber surviving history. Re-dimensioning occurs only as part of explicit structural maintenance such as qualified Move/Prepend/Normalize.
- Assets: non-artifact carriage is explicit and byte-qualified; no numeric filename sweep is authorized.
- Apply Boundary: projection precedes mutation; apply must bind to exact input bytes/paths, stage collision-safe final coordinates, fail closed on input drift/ambiguity, preserve immutable historical recovery, and emit an exact verification receipt plus post-apply audit.

## Preservation And Fidelity

- Preservation State: discovery was read-only and no current artifact bytes were changed.
- Fidelity Notes: the contract preserves the user's maintenance cases without conflating local filename compaction with Parent graph mutation. The existing process-directory anomaly is intentionally left unrepaired until the new capability can dogfood its own semantics.
- Known Losses: none; no structural apply occurred.

## Interpretation Limits

- Not Yet Used As: implementation proof, authorization to mutate current process directories, or authority to create host-specific UX before the Core contract qualifies.
- Does Not Prove: that arbitrary disconnected selections always have a unique deterministic re-dimensioning; Core must block ambiguous mappings rather than guess.
- Must Not Be Treated As: permission to infer Parent from numeric filenames, renumber after ordinary Reduction, rewrite immutable historical references, or perform remote Git mutation.
